Explain It

Short answers about how the converter works.

1. How does my app change a sound wave into binary?

My app does three steps: first it samples the wave by measuring its height at equal time steps, then it quantizes each height by rounding it to the nearest level, and finally it encodes each level as a binary number with leading zeros.

2. Test A with 2 bits vs. 6 bits: which gives more detail?

6 bits gives more detail because it has 64 levels instead of 4, so each binary value can follow the wave's height much more closely. The trade-off is that it uses more bits to store the same wave.

3. Which test has the longest wavelength?

Test B (200 Hz) has the longest wavelength at 1.72 m. Wavelength equals 343 divided by frequency, so a higher frequency gives a shorter wavelength and a lower frequency gives a longer one.

4. What was the hardest stage and how did I fix it?

The hardest part was the binary stage, because the first results had missing leading zeros and some halfway values rounded down. I fixed it by using padStart to fill the bits digits and by rounding halves up.
